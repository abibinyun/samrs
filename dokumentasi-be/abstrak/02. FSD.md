## **1. Functional Specification Document (FSD) - SAMRS**

### **A. Mekanisme Multi-Tenancy (Data Isolation)**

* **Sistem:** Setiap request ke API wajib menyertakan JWT (JSON Web Token).
* **Logika:** Di dalam JWT terdapat klaim `tenant_id`. Backend Go akan menggunakan `tenant_id` ini sebagai filter wajib di setiap query database.
* **Keamanan:** User dari Tenant A sama sekali tidak memiliki jalur akses (URL maupun Query) untuk melihat ID milik Tenant B.

### **B. Mekanisme RBAC (Role-Based Access Control)**

Sistem menggunakan **Fine-Grained Permissions**. Artinya, hak akses bukan hanya sekadar "Role", tapi daftar "Aksi" yang boleh dilakukan.

1. **Global Admin (Dev):** Mengelola pendaftaran Rumah Sakit baru dan monitoring sistem secara keseluruhan.
2. **Tenant Admin:** Memiliki hak penuh di satu RS. Bisa membuat Role baru (misal: "Kepala Teknisi") dan mencentang permission apa saja yang didapat role tersebut.
3. **Role Check:** Setiap kali user memanggil API (misal: `DELETE /assets/10`), middleware akan mengecek: *"Apakah Role user ini memiliki permission `asset:delete`?"*

### **C. Mekanisme Audit Trail (Event Sourcing)**

Setiap aksi perubahan data (`Create`, `Update`, `Delete`) akan memicu fungsi Logger.

* **Update:** Sistem akan mencatat nilai kolom sebelum diubah dan nilai sesudah diubah.
* **Penyimpanan:** Log disimpan di tabel terpisah yang bersifat *Append-Only* (hanya bisa ditambah, tidak bisa diedit/dihapus oleh user manapun termasuk Admin RS).

### **D. Alur Kerja Utama (User Stories)**

1. **Inventarisasi:** Admin menginput aset -> Sistem generate ID unik -> Admin cetak QR Code.
2. **Pelaporan Kerusakan:** Staff scan QR Code -> Isi form kerusakan -> Teknisi menerima notifikasi (Work Order).
3. **Audit:** Owner RS melihat laporan audit untuk melacak siapa yang mengubah status aset dari "Tersedia" menjadi "Rusak".

---

## **2. Aturan Bisnis (Business Rules)**

* **Asset Code:** Harus unik di dalam satu Tenant (RS), tapi boleh sama antar Tenant yang berbeda.
* **Penghapusan Data:** Menggunakan **Soft Delete**. Data tidak benar-benar hilang dari database, hanya ditandai sebagai `deleted_at` agar Audit Trail tetap terjaga integritasnya.
* **Autentikasi:** Token JWT memiliki masa berlaku (misal: 24 jam) dan mendukung *Refresh Token*.

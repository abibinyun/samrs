# **1. System Architecture & Core Database Design**

## **Technical Design Document (TDD) - SAMRS Part 1**

### **A. Database Schema (The Foundation)**

Menggunakan PostgreSQL 15 dengan pola *Shared Schema* untuk Multi-tenancy.

#### **1. Identity & RBAC Tables**

* **`tenants`**: `id` (UUID, PK), `name` (Varchar), `slug` (Varchar, Unique), `status` (Enum: active, inactive), `created_at` (Timestamp).
* **`permissions`**: `id` (Serial, PK), `name` (Varchar), `slug` (Varchar, Unique - e.g., `asset:create`), `module` (Varchar).
* **`roles`**: `id` (Serial, PK), `tenant_id` (UUID, FK - NULL for Global/System Role), `name` (Varchar), `is_system` (Boolean).
* **`role_permissions`**: `role_id` (FK), `permission_id` (FK) -> Composite PK.
* **`users`**: `id` (UUID, PK), `tenant_id` (UUID, FK), `role_id` (Integer, FK), `username` (Varchar, Unique), `password_hash` (Text), `is_active` (Boolean), `last_login` (Timestamp).

#### **2. Asset & Operational Tables**

* **`locations`**: `id` (Serial, PK), `tenant_id` (UUID, FK), `parent_id` (Integer, FK - Self Ref), `name` (Varchar), `type` (Enum: Gedung, Lantai, Ruang).
* **`assets`**: `id` (UUID, PK), `tenant_id` (UUID, FK), `location_id` (Integer, FK), `code` (Varchar, Unique per Tenant), `name` (Varchar), `brand` (Varchar), `model` (Varchar), `status` (Enum: Ready, Broken, Maintenance), `purchase_date` (Date).

#### **3. Security & Logging Table**

* **`audit_trails`**: `id` (BigInt, PK), `tenant_id` (UUID, FK), `user_id` (UUID, FK), `action` (Enum: CREATE, UPDATE, DELETE), `table_name` (Varchar), `record_id` (Varchar), `old_data` (JSONB), `new_data` (JSONB), `ip_address` (Varchar), `user_agent` (Text), `created_at` (Timestamp).

---

### **B. API Contract Standards**

* **Standard Headers:** `Authorization: Bearer <JWT_TOKEN>`, `Content-Type: application/json`.
* **Success Response (200/201):**
```json
{ "success": true, "message": "Success message", "data": { ... }, "meta": { "total": 0 } }

```


* **Error Response (403 Forbidden):**
```json
{ "success": false, "error_code": "INSUFFICIENT_PERMISSIONS", "message": "Access denied" }

```



---

### **C. Audit Trail Logic (Backend Trigger)**

Menggunakan **GORM Hooks (`AfterSave`, `AfterDelete`)**:

1. Sistem menangkap status data sebelum perubahan (*Before*).
2. Sistem membandingkan dengan status data sesudah perubahan (*After*).
3. Perbedaan (*diff*) atau seluruh objek disimpan ke dalam `audit_trails` dalam format `JSONB`.
